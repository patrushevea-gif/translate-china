# CN↔RU Ultra-Precision Translator (Conversational + Technical)

## Цель
Сделать переводчик китайский↔русский, который в реальных задачах (особенно technical) **стабильно точнее массовых движков** за счёт специализированного многослойного конвейера.

## Ключевая идея: несколько слоёв перевода
1. **Layer 1 — Multi-engine drafts**
   - Несколько движков строят независимые черновики.
2. **Layer 2 — Terminology normalization**
   - Строгая нормализация по клиентскому глоссарию + отраслевым словарям + TM.
3. **Layer 3 — Fidelity repair**
   - Исправление рисков: числа, единицы измерения, negation, обязательства и ограничения.
4. **Layer 4 — Style optimization**
   - Лёгкая стилистическая доработка без изменения фактов.
5. **Layer 5 — Back translation QA**
   - Обратный перевод и семантическая сверка.
6. **Layer 6 — Adjudication + risk gate**
   - Выбор лучшего кандидата + автоматический gate: auto-release / review / human-review-required.

## Нужен ли ИИ?
Да. Для такого уровня качества нужен **ИИ-движок** (LLM/MT API) + словари/глоссарии/правила.
- В репозитории теперь есть подключаемый backend:
  - `stub` для локальной отладки;
  - `openai-compatible` для реального AI-перевода через API.
- Без AI-провайдера инструмент остаётся только прототипом конвейера.

## Как стать точнее Google/Yandex на практике
- Нельзя честно гарантировать «100% ошибок = 0» для всех текстов.
- Можно стать **существенно точнее в целевых доменах**, если:
  - обучать/настраивать терминологию на вашем корпусе;
  - оценивать на ваших реальных датасетах договоров/инвойсов/спецификаций;
  - включить строгие quality gates для high-stakes текста.

## Что реализовано в репозитории
- `precision_translator.py` реализует многослойный CLI-прототип:
  - multi-engine черновики;
  - терминологический слой;
  - слой fidelity-repair;
  - style-polish слой;
  - scoring (glossary/numbers/units/negation/back-translation);
  - release gate и сравнительный baseline report.

## Production roadmap
- Подключить реальные API-провайдеры (LLM + MT) вместо StubProvider.
- Поднять автоматический benchmark против Google/Yandex на вашем корпусе.
- Метрики: COMET, chrF++, terminology hit-rate, numeric fidelity, legal-risk.
- Добавить режим «обязательная экспертная верификация» для критичных документов.
